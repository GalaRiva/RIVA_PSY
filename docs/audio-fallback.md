# Запасной хост для аудио (R2 → Firebase Storage)

Дата: 2026-11-08.

## Зачем

Аудио лежит на Cloudflare R2 (`pub-cd14ca249f1e4d4fbfb07ca99a7efe6d.r2.dev`). В Испании операторы
(Movistar, Orange/MásMóvil, Vodafone, DIGI) по решению суда блокируют по IP общие адреса Cloudflare
во время матчей LaLiga (мониторинг: https://hayahora.futbol). Наш хост резолвится в
`104.18.50.34` и `104.18.54.45`; оба стояли в списках блокировок. Результат: у пользователей в
Испании все треки застревают на `00:00`, без ошибки.

## Как работает

* R2 остаётся основным хостом (бесплатный исходящий трафик).
* Перед стримингом **не закэшированного** трека `AudioHostFallback.resolve()`
  (`lib/core/services/audio/audio_host_fallback.dart`) делает один запрос `Range: bytes=0-0` к R2
  (таймаут 4 с). Неудача сети, таймаут или ответ 5xx/403 = R2 заблокирован.
* При блокировке на **30 минут** все новые (незакэшированные) треки берутся с запасного хоста:
  `https://storage.googleapis.com/rigel-psy-9361c.firebasestorage.app/audio/<тот же путь>`.
* По истечении 30 минут следующий трек снова проверяет R2. Если опять не отвечает, окно
  продлевается ещё на 30 минут. Здоровый R2 повторно не проверяется 5 минут.
* Кэш на диске привязан к исходному R2-URL: трек, скачанный с любого хоста, потом играет из кэша
  без сети и без трафика.
* Единственная точка подключения: `AudioCacheManager.sourceFor` (+ `prefetch`, `probeDuration`).
  Экраны менять не нужно.

## Запасной бакет

* Бакет `rigel-psy-9361c.firebasestorage.app`, регион `europe-southwest1` (Мадрид), публичное чтение
  (`allUsers: roles/storage.objectViewer`).
* Содержимое: `audio/…` — копия R2 (тот же путь, что в Firestore `Audio.fileName*` + путь к
  дневникам «Хлебные крошки»). **Новые аудио нужно загружать в оба места** (R2 и бакет), иначе при
  блокировке нового трека на запасном хосте не будет.
* Обложки (`guided_journals/covers/*.jpg`) в копию не входят: они остаются на R2.

## Журнал использования

Каждое обращение к запасному хосту пишет **анонимный** документ в Firestore `AudioFallbackEvents`:
`ts` (время сервера), `path` (путь трека), `kind` (`play` / `prefetch` / `duration`),
`reason` (`probe_failed` = только что обнаружили блокировку, `window` = внутри 30-минутного окна),
`platform`, `locale`. Ни user id, ни device id нет. Правила: создание без входа, строго эти поля,
чтение/изменение/удаление клиентам запрещены (читать можно только через IAM/консоль).

Оценка трафика: событие `play` ≈ 4,6 МБ (средний размер трека; весь каталог 1,27 ГБ, 275 файлов).
